Anatomy of an API request

An API is a contract between two programs. A request says what to do and with which data. A response says whether it worked. Most integration problems come from what the contract does not say.

create-order.http
POST /v1/orders
Authorization: Bearer <token>

{ "items": [{ "sku": "A-1042", "qty": 2 }], "currency": "EUR" }

// 201 Created
{ "id": "ord_8123", "status": "pending" }

What to read first

  • The method and path: what is being created, read or changed
  • Authentication: who is allowed to call this
  • The status codes: 2xx worked, 4xx the caller erred, 5xx the server failed
  • Limits: how many calls per minute before requests are refused
Ask about retriesIf a request times out, can the caller safely send it again without creating a second order? The answer decides how payments and orders behave under failure.
