Events and queues in plain terms

Some work should not make the user wait. When an order is placed, the product can confirm it right away and let other systems react afterwards. The message that starts that work is an event, and the line it waits in is a queue.

order.created.json
{
  "type": "order.created",
  "id": "evt_4f81",
  "order": { "id": "ord_8123" }
}

Why users see delays

Each consumer of the event works at its own pace. If the email service is behind, the confirmation email arrives late even though the order succeeded. The product looks inconsistent because the system is eventually consistent.

Questions to ask

  • What happens if a consumer is down for an hour?
  • Can an event be delivered twice, and what then?
  • How will we know when the queue is falling behind?
